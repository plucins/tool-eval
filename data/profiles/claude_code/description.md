## Characteristics

Claude Code is Anthropic's agentic coding tool: rather than only completing code as it is typed, it independently plans and executes multi-step tasks - reading a project, editing files, running commands and tools, and iterating until a task is verified as done - reporting back rather than requiring per-step confirmation. A single natural-language instruction can produce runnable code across multiple files in one operation, extending to instruction-driven, multi-file refactors where a documented pattern has a primary agent locate every affected call site and delegate the same replacement to a sub-agent per file. When something fails, Claude Code documents running a test or build command, detecting failures, and iterating on fixes within a single continuous turn, without requiring a new prompt between attempts.

Before edits are written, Claude Code offers upfront plan review: a dedicated 'plan' permission mode routes file-edit and shell-write calls to a review callback, and a distinct ExitPlanMode tool presents the assembled plan for explicit approval before autonomous execution begins. Individual edits are then shown as a side-by-side diff the user can accept, reject, or redirect before it is written to disk, and a native checkpoint/rewind mechanism (/rewind, or Esc-Esc) automatically snapshots code state before every prompt so the user can restore code and conversation together to an earlier point. A hooks system spans the agent's action lifecycle (PreToolUse/PostToolUse and other session events); notably, a PreToolUse hook can deny a tool call even in bypassPermissions mode, letting an organization enforce policy the user cannot bypass simply by switching autonomy mode.

For large or long-running work, Claude Code documents an automatic conversation-compaction mechanism that triggers before the context window fills, plus vendor guidance for monorepos such as running an LSP server for symbol-based search and maintaining a lightweight codebase map. Two persistence mechanisms distinguish it from a stateless assistant: layered CLAUDE.md instruction files at personal, project, and enterprise-managed scope, applied through a documented, fixed precedence order, and an 'auto memory' mechanism where Claude writes and persists its own notes based on user corrections across sessions. Work can be decomposed across agent instances: a user can author custom subagents as Markdown files with YAML frontmatter defining scoped tools, a permission mode, and optional MCP servers, which the main agent delegates to and which a lead agent can also coordinate in parallel by assigning subtasks and merging results, alongside fully independent, concurrently running sessions via git worktrees, separate tabs, or multiple simultaneous cloud invocations.

Some capabilities found in adjacent tools are not documented for Claude Code. No official source describes a built-in, embedding-based semantic search across the whole codebase - Claude Code's own documentation instead frames grep/glob-based 'agentic search' as a deliberate design choice. No as-you-type ghost-text or inline code completion is documented in any IDE extension. And no fully offline/air-gapped operating mode or supported local/self-hosted model backend is documented; Claude Code always requires reaching a model-serving endpoint, whether Anthropic's own API or a customer's Bedrock, Vertex AI, or Microsoft Foundry account.

## Access methods

Claude Code's primary interface is a full-featured, standalone terminal CLI that supports editing files, running commands, and managing an entire project directly from the command line, independent of any IDE. Native extensions bring the same functionality into two officially supported IDE families - VS Code (and forks) and JetBrains IDEs. A print/headless mode (-p/--print) supports fully non-interactive, scripted invocation with structured JSON output and documented non-zero exit codes on error, and the product documents CI/CD integration via GitHub Actions and GitLab.

A browser-based 'Claude Code on the web' product lets a user connect a GitHub repository and delegate coding tasks that run on Anthropic-managed cloud infrastructure without local installation, and a dedicated 'Code' tab in the official Claude app for iOS and Android lets users start, monitor, and steer sessions - reaching cloud sessions or a session on their own machine via Remote Control - directly from a phone.

For enterprise deployment, Claude Code can run through a customer's own Amazon Bedrock, Google Cloud Vertex AI, or Microsoft Foundry account rather than only Anthropic's shared multi-tenant cloud, integrating with the customer's own IAM, audit logging, and VPC configuration; both Bedrock and Vertex additionally support VPC Service Controls/endpoints that keep model traffic entirely within the customer's private network. Region selection for data storage and model inference is documented as configurable when deployed this way (an AWS_REGION setting for Bedrock; VERTEX_REGION_<MODEL_NAME> variables or a /setup-vertex wizard for Vertex AI), and Anthropic's platform documentation separately describes configurable 'workspace geo' (data-at-rest/endpoint-processing location) and 'inference geo' (per-request model-inference location) for these cloud-provider deployment paths.

## Internal tools and mechanisms

A built-in sandboxed Bash tool provides OS-enforced filesystem and network isolation for shell commands and their child processes, confining them to defined file paths and allow-listed network domains; separately, Claude Code documents enterprise proxy allow-listing/firewall rules for the specific domains it needs, and its reference devcontainer ships an init-firewall.sh script blocking all outbound traffic except explicitly allowed domains. Terminal command execution itself follows a permission-gated model: a built-in set of read-only commands (ls, cat, git status) runs without prompting, while anything that can modify the system requires explicit approval, with sandboxing or auto-accept modes able to further reduce per-command prompts.

Long-running shell processes can be moved to the background (Ctrl+B, or by explicit request) and tracked under a task ID with output written to a retrievable file, so the interactive session is not blocked. On top of this ad hoc backgrounding, a first-party scheduling mechanism supports Desktop scheduled tasks that start a local session automatically at a chosen time or frequency, and cloud 'Routines' with recurring triggers (hourly, nightly, weekly, plus API/GitHub event triggers) that run on Anthropic-managed infrastructure independent of the user's machine.

Permission is not a single global toggle: named modes (default, acceptEdits, plan, dontAsk, bypassPermissions) behave differently per action category, and a declarative settings.json permission-rule system separately grants allow/deny/ask decisions per individual tool and pattern, evaluated in a fixed deny-then-ask-then-allow order ahead of the broader mode check. Static-analysis integration rides on the same general-purpose Hooks mechanism described above: a documented PostToolUse hook example lints newly edited TypeScript/JavaScript files with eslint and feeds failures back to Claude, though no specific linter ships built in by default.

## Workflows and use cases

Claude Code documents generating commit messages from staged and unstaged changes and carrying out branch creation and pull-request creation as part of a single guided, conversational workflow rather than only suggesting git commands as text. The dedicated GitHub Actions integration documents Claude opening pull requests directly, with read & write permissions granted specifically to create PRs and push changes, and the same integration provides a GitHub Code Review feature that posts automatic reviews on every PR without a manual trigger, alongside on-demand review via an @claude mention.

Claude Code accepts images - screenshots or design mockups - as prompt input, pasted directly into the CLI or given as a file path, and its documented use cases include generating CSS to match a design mockup, producing new code derived from visual input rather than only describing the image. Documented common workflows also include writing tests that match a project's existing style and frameworks, and instruction-driven, multi-file refactors, including a documented pattern for large-scale refactors (for example, deprecating a function used across dozens of files) where a primary agent locates every call site and delegates the same replacement to a sub-agent per file. Within a single turn, Claude Code can run a test or build command, detect failures, and iterate on fixes without a new prompt between attempts.

## Integrations

Claude Code connects to external tools and data sources through the Model Context Protocol (MCP), described in Anthropic's own documentation as reaching 'hundreds of external tools and data sources,' with pre-built servers available for systems like Google Drive, Slack, GitHub, Git, Postgres, and Puppeteer. Anthropic's official integration documentation separately lists issue-tracker/monitoring integrations (for example Sentry, via MCP) and a dedicated GitHub Actions integration for CI-driven PR creation and review handling, together spanning multiple named third-party integration categories rather than only one or two.

Beyond connecting external MCP servers, the Claude Agent SDK documents a distinct, in-process custom-tool-authoring surface - the tool() helper in TypeScript, or the @tool decorator in Python - that lets a developer register a function-based tool without configuring or running a separate MCP server process, even though it is wrapped under the hood using the MCP protocol in-process via createSdkMcpServer/create_sdk_mcp_server.

## Security

Claude Code's security documentation states user prompts and model outputs are encrypted in transit via TLS 1.2+ and that stored data is encrypted at rest by default. Organization-level access can be governed through SSO/domain capture, role-based permissions, and managed policy settings under Claude for Enterprise, plus Workload Identity Federation for short-lived OIDC-token authentication from identity providers including Okta and Microsoft Entra ID. Two admin-facing oversight surfaces are documented: a Compliance API giving Enterprise customers programmatic access to an audit-level activity feed (SSO events, API-key lifecycle, console activity), and a Claude Code Analytics API providing aggregated daily usage metrics for developer-productivity reporting.

On data retention, Zero Data Retention is documented for Claude Code - prompts and responses are processed in real time and not stored afterward - but it is explicitly excluded from the standard Claude for Enterprise plan and requires separate, per-organization enablement by Anthropic rather than a self-service admin toggle; outside ZDR, retained commercial data is documented as never used for model training without express permission. Anthropic's Data Processing Addendum, automatically incorporated into its Commercial Terms of Service, extends to Claude Code usage on Team, Enterprise, and API plans, and itemizes sub-processors in a dedicated schedule with a documented advance-notice mechanism before new ones are added. Anthropic's Commercial Terms also include an IP indemnification commitment covering paying commercial customers against copyright-infringement claims arising from authorized use, though no official source documents an accompanying filter that blocks code suggestions matching public or open-source code.

On code-security tooling, Claude Code's /security-review and 'Claude Security' capability surfaces dependency-vulnerability findings as one of several categories (alongside SQL injection, XSS, and authentication flaws) in an LLM-driven review that Anthropic's own guidance positions as complementary to, not a replacement for, dedicated deterministic dependency-scanning tools; no official page names a specific vulnerability database or enumerates covered package ecosystems. No official source describes an automatic, built-in mechanism that detects and redacts likely secrets or credentials in a prompt, file, or output before it reaches the model or disk; the generic Hooks system could be used to build such a check, but no first-party secret-detection feature ships out of the box.

This summary reflects vendor documentation only and is not legal advice; teams with specific GDPR, data-residency, or contractual DPA requirements should confirm current terms with Anthropic and consult Legal/the Data Privacy Officer before relying on it for a compliance decision.

## Constraints

Several capabilities are gated by plan, license, or deployment path rather than being universally available: SSO, domain capture, and role-based permissions are documented specifically under Claude for Enterprise; Zero Data Retention requires a qualified Enterprise account with separate enablement by Anthropic's account team rather than a standard admin toggle; and the IP indemnification commitment applies to paying commercial customers (Team, Enterprise, API) rather than free users. Enterprise/private deployment is achieved through a customer's own Amazon Bedrock, Google Cloud Vertex AI, or Microsoft Foundry account (optionally with a self-hosted gateway), rather than a vendor-provided, fully air-gapped on-premises product, and native region selection for data storage/inference is documented only for those cloud-provider deployment paths, not the default Anthropic-hosted path.

Some mechanisms require additional setup: automated PR review and PR creation depend on installing the Claude GitHub App and its GitHub Actions workflow, or the equivalent GitLab CI/CD integration; static-analysis/lint feedback relies on a user-configured Hooks pipeline, since no linter ships bundled by default; and most third-party MCP integrations require explicitly adding the relevant MCP server. A PreToolUse hook that returns a 'deny' decision blocks a tool call even in bypassPermissions mode, but ordinary PostToolUse hooks can only observe and react to an already-completed action, not undo it.

Several areas fall short of a full match against documented capability: native codebase search is grep/glob-based 'agentic search' rather than built-in embedding-based semantic search, and dependency-vulnerability findings come bundled inside a broader LLM-driven security review rather than a dedicated, named CVE-database-matched SCA integration. No official source documents as-you-type inline/ghost-text code completion in any IDE extension, a fully offline/air-gapped operating mode, a supported local/self-hosted model backend, or a built-in automatic secret-detection/redaction mechanism - each was checked across documentation, product, changelog, and pricing sources with a consistent negative result.
