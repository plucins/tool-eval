## Characteristics

Claude Code is Anthropic's agentic coding tool: rather than completing code as you type, it reads a codebase, plans a multi-step approach, edits files, runs commands, and iterates until a task is done, reporting back once it has verified the result. A single natural-language instruction can produce runnable code spanning multiple files in one operation, and this extends to instruction-driven, multi-file refactors and general git workflows (creating commits with generated messages, branches, and pull requests) driven entirely through conversation rather than IDE-specific commands.

Two persistence mechanisms distinguish it from a stateless assistant: CLAUDE.md files give it project, personal, or organization instructions that it reads at the start of every session, and an 'auto memory' feature lets it accumulate its own notes (build commands, debugging insights, architecture conventions, style preferences) across sessions without the user re-entering them. For large or long-running work, Claude Code documents an extended (up to 1M-token) context window on recent models (Claude Sonnet 5, Opus 5) and Pro/Max/Team/Enterprise plans, with automatic summarization of the in-progress task when a context window nears its hard limit, plus guidance to scope work to relevant subdirectories in large monorepos.

Claude Code can also decompose work across agent instances: subagents are separate agent instances the main agent can spawn to handle focused subtasks in their own context windows, and a dedicated 'Run agents in parallel' guide documents patterns (parallel sessions via worktrees, agent teams, forked subagents) for coordinating several agents at once. A first-party Code Review capability (research preview, Team/Enterprise only) extends this agentic model to GitHub pull requests, using a fleet of specialized agents to post inline comments on logic errors, security issues, and regressions, tunable per repo via a REVIEW.md file.

## Access methods

Claude Code's primary interface is a terminal CLI that runs independently of any IDE, available on macOS, Linux, and Windows. Native extensions bring the same functionality into two IDE families - VS Code (and forks such as Cursor and Devin Desktop) and JetBrains IDEs - so the agent can work alongside a developer's existing editor rather than replacing it.

A browser-based 'Claude Code on the web' product (research preview, at claude.ai/code) lets a user connect a GitHub repository and delegate coding tasks that run on Anthropic-managed cloud infrastructure without any local installation, reviewing the resulting pull request when done; it is available to Pro, Max, and Team users, and to Enterprise users with premium or Chat + Claude Code seats. Anthropic has also added an official Claude mobile app for iOS and Android that acts as a remote client: from a phone, a user can start, monitor, and steer a cloud session, a session on their own machine (via Remote Control), or the Desktop app (via Dispatch), and receive push notifications when a task finishes or needs a decision.

For enterprise deployment, Claude Code can run against models hosted in a customer's own Amazon Bedrock, Google Cloud Vertex AI, or Microsoft Foundry account rather than only Anthropic's shared multi-tenant cloud, optionally routed through a self-hosted 'Claude apps gateway' that adds organization SSO and telemetry across all three cloud paths.

## Internal tools and mechanisms

A built-in sandboxed Bash tool restricts every shell command Claude runs using OS-level primitives - Seatbelt on macOS, bubblewrap on Linux and WSL2 - limiting filesystem writes to the working directory and network access to a proxy allowlist; sandboxing can be toggled with a /sandbox command and enforced organization-wide via managed settings, and isolation options range from this lightweight per-command sandbox up to dev containers, Docker, or a fully separate virtual machine (including Anthropic-managed cloud VMs for Claude Code on the web).

In the default permission mode, every proposed file edit is shown as a side-by-side diff that the user must accept, reject, or redirect before it is written to disk; other permission modes (AcceptEdits, Plan, Bypass) auto-approve edits or skip this inline review step. Long-running shell processes (dev servers, test watchers, builds) can run in the background so the session is not blocked, with the agent able to poll or stop them later. A Hooks system lets teams wire deterministic checks into the agent's workflow, for example a PostToolUse hook that runs a linter automatically whenever Claude writes or edits a file, feeding the results back into the agent's own workflow, since CLAUDE.md instructions alone are only advisory.

## Workflows and use cases

Documented common workflows include writing tests for untested code (matching the style, frameworks, and assertion patterns of a project's existing tests), fixing lint errors, resolving merge conflicts, updating dependencies, and writing release notes, alongside instruction-driven multi-file refactors. Git operations - committing with an auto-generated descriptive message, branching, and (once the GitHub CLI is installed and authenticated) creating pull requests and reading or responding to PR comments - are handled conversationally rather than through separate git commands.

On Team and Enterprise plans, the Code Review capability extends this to automated GitHub PR review: specialized agents examine a diff in the context of the whole codebase and post inline comments on logic errors, security vulnerabilities, and regressions, with review behavior tunable per repo via a REVIEW.md file that takes precedence over default guidance. For onboarding to or working in large codebases, Claude Code recommends starting in relevant subdirectories, using layered root/subdirectory CLAUDE.md files and on-demand skills, and relying on its native grep/glob-based 'agentic search' (optionally augmented by installing a third-party MCP plugin such as Sourcegraph or Greptile for embedding-based semantic search) rather than requiring a prebuilt codebase index.

## Integrations

Claude Code connects to external tools and data sources through the Model Context Protocol (MCP), an open standard that Anthropic's own documentation says can reach 'hundreds of external tools and data sources' once the relevant MCP server is configured and connected, exceeding a narrow one- or two-integration catalog. Anthropic also maintains an official plugin catalog of specific MCP-based add-ons, including a Sourcegraph plugin (semantic search, symbol navigation, and Deep Search over a connected Sourcegraph instance) and a Greptile plugin (natural-language codebase queries), both of which supply capabilities, notably embedding-based semantic search, that are not part of Claude Code's native, index-free agentic search. GitHub integration for issue/PR workflows is delivered through the GitHub CLI (gh) rather than a bespoke connector: once gh is installed and authenticated, Claude Code can create issues, open pull requests, and read comments directly from a session.

## Security

Organization-level access is governed through SAML 2.0/OIDC single sign-on, SCIM and JIT provisioning (SCIM restricted to Enterprise and Console organizations), groups and role-based/custom permissions, and managed policy settings enforced from the admin console, an MDM system, or a settings file, taking precedence over local developer configuration. Command execution itself follows a permission-based model (a small set of read-only commands like ls, cat, and git status runs without a prompt; anything that can modify the system requires explicit approval) and, separately, every Bash command can be constrained by the OS-level sandbox described above.

On data handling, Anthropic states it does not train generative models on code or prompts sent to Claude Code under commercial terms (Team, Enterprise, API, third-party platforms, Claude Gov) unless a customer explicitly opts in, and commercial/enterprise organizations can configure custom data retention or zero-data-retention arrangements. For governance and audit purposes, an organization-scoped Compliance API exposes a queryable activity feed of admin/system events (e.g. membership changes, API key creation, account setting updates), though it explicitly does not log inference activity such as prompts or conversation content; a separate Claude Code Analytics API/dashboard reports aggregated usage metrics (sessions, lines of code changed, commits, pull requests) for organization admins. Anthropic's commercial/API terms also include an IP indemnification commitment, defending customers against third-party copyright-infringement claims arising from authorized use of the service or its outputs, subject to standard carve-outs, though no official Claude Code documentation describes a configurable filter that blocks suggestions matching public code.

## Constraints

Several capabilities are gated by plan or organization type rather than universally available: Code Review is limited to Team and Enterprise subscriptions and is unavailable where Zero Data Retention is enabled; SCIM automated provisioning is restricted to Enterprise and Console organizations; the 1M-token context window requires Pro, Max, Team, or Enterprise plans on recent models; and Claude Code on the web requires a Pro, Max, or Team plan, or an Enterprise plan with premium or Chat + Claude Code seats. A number of newer surfaces remain in research preview rather than general availability, including Code Review and Claude Code on the web, per the vendor's own current documentation.

Some mechanisms require additional setup: pull request creation depends on the GitHub CLI being installed and authenticated, otherwise falling back to rate-limited unauthenticated GitHub API access; static-analysis/lint feedback requires configuring a PostToolUse hook, since no linter ships bundled; and the sandboxed Bash tool's Linux/WSL2 isolation depends on manually installing bubblewrap and socat, while macOS's Seatbelt backend needs no extra install. Enterprise/private deployment is achieved through a customer's own Amazon Bedrock, Google Cloud Vertex AI, or Microsoft Foundry account, optionally behind a self-hosted gateway, rather than a fully air-gapped, vendor-independent on-premises product.

Two areas fall short of a full match against their taxonomy criteria: native codebase search is grep/glob-based 'agentic search' rather than built-in embedding-based semantic search (whole-repo semantic search requires installing a third-party MCP plugin such as Sourcegraph or Greptile), and the documented IP-indemnification commitment has no accompanying, documented public-code/duplication-matching suggestion filter. No official source describes as-you-type inline/ghost-text code completion in any IDE extension; Claude Code's documented autocomplete behavior is limited to command-UI conveniences (slash commands, @-mentions, shell history), not inline source-code completion.
