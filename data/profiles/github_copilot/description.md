## Characteristics

GitHub Copilot combines interactive coding assistance with agent-driven development across editors, a standalone terminal agent, GitHub.com, mobile, and a dedicated desktop app. The supplied merged findings establish inline completion, natural-language and multi-file generation, test generation, refactoring, image-derived code generation, and dedicated pull-request review. These are different workflows, not interchangeable names for one chat interface.

IDE agent mode can inspect a project, select files, edit code, run commands, and iterate on validation failures. CLI adds explicit planning, configurable tool permissions, autonomous continuation, custom agents, and coordinated subagents. Cloud agent performs delegated repository work asynchronously and can prepare a pull request for human review. Independent app sessions use separate branches/worktrees; CLI `/fleet` instead coordinates subtasks within one request. Neither concurrency mechanism guarantees faster or correct results.

This profile synthesizes the supplied final feature records without changing their statuses. The current source checks and release capture are dated **October 11, 2026**. Product-level `has` findings should be read with their client, plan, model, policy, and release-stage constraints, not as feature parity across every Copilot surface.

## Access methods

Use [Copilot in an IDE](https://docs.github.com/en/copilot/concepts/copilot-surfaces/copilot-in-ides) for inline suggestions and interactive chat/agent work. The merged matrix lists completion in VS Code, Visual Studio, JetBrains, Eclipse, Xcode, and NeoVim; NeoVim does not have the same chat, agent-mode, or MCP support. Install a supported integration and sign in with the appropriate account. The October 10 JetBrains announcement now requires IDE **2025.2 or later**; older general compatibility information is not sufficient for the latest plugin.

[Copilot CLI](https://docs.github.com/en/copilot/concepts/copilot-surfaces/copilot-cli) runs independently of an IDE on Linux, macOS, and Windows through PowerShell or WSL. It supports interactive conversations and a programmatic prompt-and-exit interface. The npm installation channel requires Node.js 22+, while standalone executables and other channels are also documented. Plan before editing in interactive plan mode, or configure authentication and narrowly scoped permissions for unattended work. Local BYOK is a distinct access path: the merged findings establish that it does not require a Copilot subscription, while hosted Copilot usage depends on entitlement and policies.

GitHub.com provides browser chat, repository questions, review, and cloud-agent delegation without a local IDE. Cloud agent works with GitHub-hosted repositories, not arbitrary hosting platforms. GitHub Mobile supplies official Android/iOS chat access, not a mobile code editor. The Copilot app runs on macOS, Linux, and Windows and coordinates parallel repository work; the current plans page includes both app and CLI in all plans, with usage and administrator controls still applying. The [surface guide](https://docs.github.com/en/copilot/get-started/where-to-use-github-copilot) also identifies SDK-powered custom applications and GitHub Desktop commit-message assistance; those are separate access methods, not full IDE equivalents.

## Internal tools and mechanisms

The merged findings establish file inspection/editing, terminal command execution, Git operations, repository semantic retrieval, and validation-driven iteration. Repository indexing enriches GitHub/VS Code Chat and cloud-agent context; it should not be generalized to every IDE. Non-GitHub workspace indexing in VS Code uploads workspace data to GitHub and requires the applicable policy enablement. CLI manages long sessions by compacting history into summaries, preserving instructions and plan state but losing fine detail. The dedicated [context-management page](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/context-management) describes background compaction around 80% and a pause near 95% if needed; this is not unlimited verbatim memory.

CLI has named explore, task, general-purpose, code-review, research, rubber-duck, and security-review specialists. Custom Markdown/YAML profiles can specify prompts and tools; subagents have separate context windows. `/fleet` can coordinate dependencies and parallel work where suitable, potentially increasing credit consumption. The task specialist runs available project build/test/lint/format commands; this does **not** substantiate a universally bundled formatter or linter.

Repository instructions persist across requests, but supported scopes and instruction formats differ by client. The verified personal/repository/organization precedence belongs to GitHub.com, not every IDE or CLI session. Repository JSON hooks for CLI/cloud agent can run at lifecycle and tool-use events, including approval/denial before tool use. SDK custom tools and experimental JavaScript CLI extensions provide native callable-tool registration in their respective surfaces. Experimental extensions and opt-in planning should not be presented as mandatory behavior for all requests.

## Workflows and use cases

Documented workflows include understanding unfamiliar code, generating new files or project scaffolds, repairing/refactoring existing code, and writing tests for selected code with framework and edge-case instructions. Image-to-code examples use UI mockups or screenshots in supported IDE Chat clients with an image-capable model; the merged matrix retains client-specific preview markers. Generated code and tests still need execution and review.

A terminal issue-to-PR workflow can begin with an issue URL, proceed through an implementation plan and permitted edits/commands, and create a GitHub pull request. Cloud agent instead researches, plans, and implements delegated work in the background. It operates on one repository and branch, can open one PR per task, and has a 59-minute maximum session runtime. Humans should review output before merging; Actions workflows on agent pull requests require approval by default.

Native automations support recurring hourly/daily/weekly schedules and repository-event triggers. Official examples include issue triage, nightly failing-test repair attempts, and weekly release-note drafts. They require private/internal repositories, write access, enabled policies, and an eligible paid plan. Automations are not stored/versioned in Git; their sessions and logs are visible to repository readers even though configuration is private to the creator.

For automation outside that UI, the merged headless finding is specifically grounded in CLI programmatic interfaces, JSONL output, and a direct dynamic-workflow mode with documented exit codes. Its workflow registration/trust requirements and exit-code table must not be assumed to cover every ordinary `-p` invocation. Parallel modernization is an **inferred** combined workflow using independent app sessions, `/fleet`, tests, and PR review; it is not a documented performance claim.

## Integrations

The supplied official integration catalog establishes cloud-agent integrations with **Microsoft Teams, Slack, Linear, Azure Boards, and Jira**. These bring conversation, issue, or work-item context into GitHub repository changes and pull requests. The count describes that catalog, not every possible plugin or MCP connector. Teams and Slack remain public preview and require app installation, account linking, repository permissions, and enabled cloud sandboxes. Linear setup requires the appropriate GitHub/Linear administration; Azure Boards requires its GitHub app and project authorization; Jira requires Jira Cloud AI/Rovo and both application installations. Enterprise data-residency installations can use separate GHE.com routes.

[MCP](https://docs.github.com/en/copilot/concepts/context/mcp) is the broader extensibility mechanism. CLI supports local and remote servers, the app can reuse repository/CLI configuration, and repository settings serve cloud agent and code review. GitHub and Playwright servers are documented defaults in those GitHub.com agent/review workflows. Local/remote transports and authentication vary by client, and Business/Enterprise MCP policy is disabled by default. Registry listings from partners or the community are discoverable extensions, not automatic endorsements or universal compatibility guarantees.

The October 2 code-review announcement additionally establishes GA REST/GraphQL review requests with per-request effort selection for paid plans. Native SDK tools and experimental CLI extensions are distinct from MCP and from the five cloud-agent catalog integrations.

## Security

Security controls are scope-specific. CLI can allow/deny tool categories, shell subcommands, and paths; deny rules override allows. Autonomous continuation does not remove permission requirements. VS Code can show a diff and request approval **before** configured file edits, whereas ordinary pending Keep/Undo changes are already saved. Agent Host has a different review state, and pre-apply edit approval does not prove interception of arbitrary script or terminal writes. Checkpoints/CLI rewind restore tracked workspace changes and conversation state within documented limits, not deployments, network calls, or other external side effects.

[Local sandboxing reached GA on October 7](https://github.blog/changelog/2026-10-07-local-sandboxing-for-github-copilot-now-generally-available/) in CLI, the app, and VS Code Agent Host sessions. It is included at no extra charge and uses native OS containment; the merged documentation notes opt-in defaults, OS differences, and best-effort handling for in-process file tools. Cloud sandboxes remain separately documented public preview, usage-billed, and restricted to supported interactive CLI sessions. Tool isolation is not model/data-location isolation. Cloud agent also has a configurable egress firewall with organization/repository allowlists, but its Bash-process boundary does not cover every MCP/setup process and GitHub warns of bypass risk.

Cloud-agent generated-code validation integrates CodeQL, secret scanning, and new-dependency checks against the Advisory Database for malware and High/Critical vulnerabilities; administrators can disable validation. Supported remote GitHub MCP push protection can block secrets in mediated responses/actions, subject to repository security coverage and bypass rules. This is not universal pre-inference prompt redaction or prevention of every local write. The October 7 secret-classifier announcement explicitly separates existing alerts from future opt-in Copilot checks; coming-soon/private-preview capabilities are not asserted as generally available.

Business/Enterprise governance includes SSO/identity-provider integration, granular policy roles, audit events, and exportable usage reports. Training opt-out differs between individual and organizational plans and is not zero retention. The merged DPA finding remains organizational/GA-and-covered-preview scoped; public-code filtering is verified but output legal defense depends on the customer's agreement and mitigations. HTTPS transit encryption is verified; at-rest encryption remains unverified because the supplied research had material Trust Center access gaps. Enterprise data-residency controls can restrict inference to certified US/EU models when explicitly enabled, with compatible clients and a 10% credit overhead; they are not a default global guarantee.

## Constraints

As checked October 11, [plans](https://docs.github.com/en/copilot/get-started/plans) include Free, verified Student, Pro, Pro+, Max, Business, and Enterprise. Published monthly prices are USD 10/39/100 for Pro/Pro+/Max and USD 19/39 per granted seat for Business/Enterprise. Current allowances are AI-credit based: paid individual totals include both base and flex amounts (1,500/7,000/20,000 respectively), while Business/Enterprise list 1,900/3,900 per user/month. Free has 2,000 inline completions/month and limited agents; Free/Student use auto model selection. These are current checked values, not historical premium-request quotas. Model access, additional paid usage, cloud sandbox costs, Actions consumption, and organization policies can further constrain work.

Model support changes over time. Haiku 5.5 was announced GA October 7 for paid plans with gradual rollout and policy controls. The October 2 deprecation notice removes Gemini 3.5/3.6 Flash, Kimi K2.7 Code, and Claude Opus 4.7; historical availability posts should not override it. Image input requires a capable model, code review does not offer ordinary user model switching, and residency restrictions narrow the usable model set. CLI extensions and certain IDE/BYOK or vision experiences retain their documented experimental/preview scope. Cloud sandboxes and Teams/Slack previews must not be conflated with CLI or local sandbox GA.

The supplied **full offline operation** and **on-premises/private deployment** records remain `uncertain`. CLI local-provider offline mode is separately documented: it prevents GitHub contact only when explicitly configured, and complete network isolation also requires a local/isolated provider. Merely selecting Ollama neither enables offline mode nor disables telemetry. This narrower supported path does not prove every Copilot surface works offline or that the Copilot service can be self-hosted. Self-hosted Actions runners relocate agent execution infrastructure, not the entire service. GitHub Enterprise Server remains explicitly unsupported for Copilot; the planned GHES security-alert model is a different product capability.

Usage reports also have quality limits. Besides telemetry, client-version, and reporting-delay requirements in the merged findings, the October 6 notice identifies SDK-based IDE agent attribution loss and historical CLI inflation. VS Code 1.139.0+ has a fix; other IDE fixes were expected later, and missing data cannot be backfilled. General minimum telemetry versions do not establish complete agent reporting. The profile records these newer caveats and scope tensions without rewriting the final merged feature statuses.
