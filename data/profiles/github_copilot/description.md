## Characteristics

GitHub Copilot is GitHub's AI pair-programming product, built directly into the GitHub platform and spanning a wide range of surfaces: inline "ghost text" completions in the editor, a conversational Copilot Chat, a multi-file "Copilot Edits" experience with dedicated edit and agent modes, a fully autonomous cloud/coding agent, and a standalone terminal CLI. At its core it turns natural-language prompts into runnable code and can act on that code directly -- writing across files, running terminal commands, and iterating on failing tests and build errors without a fresh prompt -- before opening a pull request once the work is complete.

A distinctive part of Copilot's design is its multi-agent structure. A documented "plan agent" mode drafts and shares a step-by-step plan, using only read-only tools, for the user to review before any files are touched, while agent mode or the coding agent then carries out the approved plan. Developers can also define their own named custom sub-agents (`.agent.md` files with their own prompt and tool scope) that the parent agent automatically delegates matching requests to, and Copilot CLI can fan work out to several sub-agents in parallel via a `/fleet` command.

Copilot builds and automatically maintains a per-repository semantic code index so natural-language questions can be answered by meaning rather than plain-text matching, and its latest models support an extended, documented-up-to-1-million-token context window on select surfaces (VS Code, Copilot CLI, the GitHub Copilot app) for reasoning across large, multi-file codebases -- though this remains tied to specific models and surfaces rather than being universally available. Multimodal input is supported through Copilot Vision, letting a developer attach a screenshot, mockup, or PDF to a chat prompt and have Copilot reason about it alongside the surrounding code.

## Access methods

Copilot is reachable from essentially anywhere a developer works. Inline completions and Copilot Chat are documented across a wide span of editors -- Visual Studio Code, Visual Studio, JetBrains IDEs, Neovim/Vim, Xcode, Eclipse, and Azure Data Studio -- well beyond a token one- or two-IDE integration. Copilot Chat is also available directly in the browser on GitHub.com, in GitHub Mobile (iOS and Android), and in Windows Terminal, so a user is not required to install anything locally to converse with Copilot or to hand a task to the coding agent, which can be triggered simply by assigning a GitHub Issue from github.com, GitHub Mobile, or the CLI.

For developers who prefer the terminal, GitHub ships a standalone `copilot` command-line tool (distributed as the `@github/copilot` npm package) that brings chat, editing, and command-execution capability directly to a local shell session and has formally superseded the older `gh copilot` GitHub CLI extension. Copilot CLI directly executes shell commands on the user's behalf, subject to an explicit permission-prompt/approval model before each command runs. Copilot CLI and the GitHub Copilot desktop app both document Bring-Your-Own-Key (BYOK) support for pointing agent sessions at third-party or fully local model providers -- OpenAI, Azure OpenAI, Anthropic, and locally running models such as Ollama, vLLM, Foundry Local, and LM Studio -- instead of GitHub's own hosted models, provided the connected model supports tool calling and streaming.

## Workflows and use cases

Beyond simple completions, Copilot documents an autonomous, end-to-end delivery workflow: its coding/cloud agent can independently plan and execute a sequence of actions -- creating a branch, editing code, running tests and linters, and iterating on failures -- to complete a task picked up from an issue, PR comment, or chat prompt, then opens or updates a pull request without requiring step-by-step confirmation, continuing to run in the background even after the requester's machine is off. The coding agent's "agents panel" and Copilot CLI's `/fleet` command both let a user fan multiple independent tasks out to run in parallel rather than working through them serially.

Chat and Copilot Edits extend into everyday development tasks: generating unit tests, mocks, and end-to-end tests on request; suggesting refactors -- design patterns, decoupling data access from business logic, removing deep class inheritance -- across more than a single symbol rename; producing commit messages and, via the cloud agent, full branch/commit/PR sequences; and reviewing pull requests as a dedicated Comment-type review that can incorporate CodeQL, ESLint, and PMD findings directly into its feedback.

Security-adjacent workflows are documented too: Dependabot alerts can be assigned to Copilot to analyze a CVE and open a draft fix PR, and Copilot CLI can run non-interactively inside a GitHub Actions workflow for headless CI/CD automation. Recurring or delayed work is supported through the GitHub Copilot app's schedule-based automations (hourly/daily/weekly triggers for saved agent tasks) and Copilot CLI's `/every`/`/after` slash commands within an active session.

## Integrations

GitHub documents first-party support for the Model Context Protocol (MCP) across Copilot Chat in IDEs, the cloud/coding agent, Copilot CLI, and the Copilot SDK, letting Copilot call out to externally hosted tools and data sources; the cloud agent and Copilot code review are currently limited to invoking MCP tools rather than the resources or prompts an MCP server may also expose. Copilot's coding/cloud agent can additionally be triggered directly from third-party planning and collaboration tools -- GitHub's own integrations documentation names Microsoft Teams, Slack, Linear, Azure Boards, and Jira -- and GitHub's own Marketplace hosts a vendor-curated catalog of Copilot Extensions from companies such as Docker, Sentry, MongoDB, Stripe, LaunchDarkly, and Atlassian, usable from Copilot Chat on GitHub.com, Visual Studio, and VS Code. Each of these integrations requires the customer to separately connect or install the relevant third-party workspace, account, or extension.

## Security

GitHub documents a layered set of security and data-handling controls around Copilot. Data in transit is encrypted via TLS, and any Copilot-related data retained at rest is encrypted under Microsoft Azure's FIPS 140-2-aligned encryption. Enterprise Cloud admins can enforce a data-residency policy that keeps Copilot inference processing within a chosen US or EU (including EFTA) region, paired with FedRAMP-authorized model options; individual-tier subscribers can separately opt out, in personal settings, of having their interactions used for model training, while Copilot Business and Enterprise customer data is excluded from training by default under GitHub's Data Protection Agreement. That DPA is a standing, generally available document rather than one gated behind a special request, and GitHub publishes a corresponding sub-processor list with a documented 30-day advance-notice commitment before a new sub-processor is authorized -- though that same page frames its applicability around GitHub's Enterprise customers under the DPA rather than individual free-tier use.

Administrative audit logging (e.g. seat assignment, policy changes) is documented for organizations and enterprises on a Copilot Business plan or higher; SAML SSO and custom organization roles extend the underlying GitHub Enterprise account's access-control model to Copilot. On the execution side, the coding/cloud agent runs inside its own ephemeral sandbox behind a configurable outbound-network firewall (a "recommended allowlist" of common package/container registries, on by default and adjustable or fully disable-able by admins), though this firewall applies only to the agent's own Bash-tool processes -- not to MCP servers or to Copilot CLI's local terminal sessions.

Secret handling is only partially covered: Copilot CLI redacts GITHUB_TOKEN and COPILOT_GITHUB_TOKEN by default (extendable to other named environment variables via a flag), while GitHub's separate "content exclusion" feature is a manually configured file-path allow/deny list that explicitly does not apply to Copilot CLI, the cloud agent, or IDE agent mode -- so there is no documented, broad, pattern-based secret scanner covering all of Copilot's surfaces. Non-official sources also describe an IP indemnification commitment tied to Copilot's public-code duplication-detection filter for Business/Enterprise customers; this could not be corroborated against an official GitHub page in this research pass, so it should be treated as unverified, and any contractual or IP-indemnity questions should be routed to Legal/Compliance rather than relied on from this summary.

## Constraints

Several of Copilot's more advanced capabilities are gated to specific plans: Copilot code review and coding/cloud agent pull-request creation are documented as available with Copilot Pro, Pro+, Business, or Enterprise; audit logging, the published sub-processor list, and enforced data residency are documented for Copilot Business/Enterprise and GitHub Enterprise Cloud accounts rather than individual Free/Pro subscribers; and SAML SSO/custom organization roles depend on the underlying GitHub Enterprise account tier rather than being Copilot-specific settings.

Some capabilities are further scoped to particular surfaces: the extended one-million-token context window and BYOK/local-model support are documented only for specific "latest" models and are currently available in VS Code, Copilot CLI, and the GitHub Copilot app rather than every surface; the sandboxed execution environment and its outbound-network firewall apply to the cloud/coding agent, while Copilot CLI's agent mode instead runs commands directly in the user's own local terminal; and content exclusion (file-path based) explicitly does not apply to Copilot CLI, the cloud agent, or IDE agent mode.

Two areas remain unresolved rather than confirmed absent, per the research protocol's negative-finding rules: whether Copilot supports a fully offline mode (documentation points to a direct HTTPS dependency on GitHub's servers, but not every source class could be checked) and whether an on-premises/private deployment option exists (a "GitHub Enterprise Local" offering surfaced only via Microsoft-owned pages, not a GitHub-owned source, so it could not be used to justify a status). A number of newer features -- linter (ESLint/PMD) integration in Copilot code review, the plan-first agent workflow, and Dependabot-to-Copilot alert assignment -- are documented as being in public preview or as recently introduced, so behavior and availability may still evolve.
