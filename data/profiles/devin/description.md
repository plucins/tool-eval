## Characteristics

Devin is Cognition's coding-agent product family, with materially different Cloud, CLI, and Desktop surfaces. **Devin Cloud** provides autonomous repository work in a session machine: code generation, coordinated multi-file changes, commands, testing, refactoring, and pull-request creation. Ask Devin provides read-only codebase exploration and an optional plan-to-Agent handoff; it is not the implementation mode. Background Cloud sessions and independent parallel tasks are supported, as is coordinator-led delegation to managed child sessions. These are documented capabilities, not measured guarantees of correctness or delivery speed.

**Devin CLI** defaults to a local coding agent and has its own permission system, tools, hooks, and subagents; `--cloud` instead connects to an actual Cloud session. **Devin Desktop** is the officially documented rebrand of the Windsurf IDE, with current Desktop-specific inline completion and editor generation features. This profile uses that explicit continuity only where supported by current Devin documentation. It does not attribute unrelated legacy Windsurf or Codeium plugin functionality to Cloud.

## Access methods

**Browser:** the merged findings confirm core coding access at [app.devin.ai](https://app.devin.ai), including Agent sessions and a hosted IDE for monitoring and takeover. Repository indexing, environment setup, account access, and usage allowances apply. The documented mobile-web experience includes session navigation and notifications; `mobile_app_access` remains partial, not a claim of a verified dedicated iOS/Android app.

**Terminal:** the standalone CLI is documented for macOS, Linux, WSL, and native Windows. Default sessions run locally; `devin --cloud` streams a Cloud session working on its own VM. Handoff moves work to Cloud so it can continue after the user's laptop closes. Headless print execution exists, but its merged finding is partial: coding-task completion exit-code semantics were not established, and Cloud print mode can exit while the persistent session continues.

**Desktop and other editors:** Devin Desktop supplies a full editor and local-agent interface, with current documentation confirming Tab inline completion. Devin CLI integrates through ACP with JetBrains AI Chat, Zed, and Xcode; these are local/CLI integrations, not universal Cloud embedding. Xcode's coding-assistant integration requires 26.6 or later. Teams Desktop access requires a full seat; legacy Desktop subscriptions and Cloud enterprise SKUs should not be treated as interchangeable.

## Internal tools and mechanisms

Cloud sessions expose shell, browser, and IDE tools, with clean environment snapshots for new sessions. Ask Devin uses indexed repository context and cited code answers; the merged `codebase_semantic_search` finding remains uncertain because the required meaning-based retrieval/ranking mechanism was not established. Large-repository handling is supported by concrete context mechanisms rather than an asserted unlimited context window: indexed handoffs, CLI lazy loading of directory instructions, and Security Swarm's task-specific repository partitioning.

Local CLI sessions offer read-only planning, scoped Read/Write/Exec/Fetch/MCP approvals, lifecycle hooks that can block or rewrite actions, and `/revert` restoration of file and conversation changes from a selected step. That rollback is not a reversal of external side effects. Built-in Explore and General subagents have separate conversation chains and distinct model-selection behavior; background workers cannot request new permissions. Custom worker definitions remain experimental and local-only. Plugin hooks are best-effort and can fail open, so they should not be described as mandatory security controls.

Repository `AGENTS.md` and rules provide persistent guidance; only the first 16 KiB of each AGENTS.md file is automatically injected. Personal organization-scoped Memory is distinct from shared project instructions and is not used by automation-started sessions. Multiple rule scopes are confirmed, but the merged instruction-precedence finding remains partial: plugin-governance hierarchy does not establish precedence between contradictory instruction texts.

## Workflows and use cases

The documented use cases include containerizing a Django service, implementing structured Figma designs through an authorized MCP connection, adding unit/integration coverage, running independent backlog items in parallel, iterating on Review and CI failures with Auto-Fix enabled, and scheduling recurring maintenance through Automations. These examples have different prerequisites and evidence strengths. Figma design-to-code is not proof of generic screenshot-to-new-code generation, and dependency maintenance is not proof of database-backed dependency vulnerability scanning.

A practical Cloud workflow is to explore and scope in Ask Devin, review the generated plan, explicitly send it to Agent mode, and inspect the resulting tests and PR. Plan-first handoff is optional; directly launching Agent mode is also supported. Multi-agent Cloud coordination is distinct from independent parallel sessions and from local CLI workers. Automations support recurring and future one-time runs through RRULE schedules with time zones; legacy Schedules is not the current creation interface.

The locally supervised refactor use case is explicitly **inferred** from verified planning, permission, testing, refactoring, and rollback capabilities. It is not presented as a separate vendor recipe. Across workflows, scope the task, provide repository conventions and success criteria, and review outputs rather than interpreting autonomy as a correctness guarantee.

## Integrations

The merged native integration catalog names GitHub, GitLab, Bitbucket, Azure DevOps, Slack, Microsoft Teams, Jira, Linear, PagerDuty, and Pylon, with additional Databricks and MongoDB connection guides. This is a documented set, not an exhaustive integration count. Native connections, MCP servers, and plugin packages are separate mechanisms; installation does not automatically authorize access to external services. Custom Cloud MCP supports STDIO, SSE, and HTTP and requires the appropriate management permission and credentials.

Provider capabilities and entitlements differ. GitLab Self-Managed support is Enterprise-scoped and documents version 15.0 or later; Azure DevOps setup directs users to an Enterprise account; Pylon is catalogued as beta. Devin Review supports provider-specific PR review, but Bitbucket Data Center requires 8.16 or later and Bitbucket Cloud is not supported by Review. GitHub Review write actions require the GitHub App connection; PAT-based access is read-only. Repository PR creation support must not be confused with identical Review support across providers.

MCP extensibility is confirmed. Native non-MCP callable-tool registration remains uncertain; skills, plugin hooks, workflow scripts, and changelog mentions of scripted tools do not by themselves establish that interface.

## Security

The merged findings confirm encrypted transit/storage, Enterprise SAML/OIDC SSO and granular RBAC, and Cloud security profiles with destination allowlists. Enterprise event-level audit logging is verified but rated partial under the assigned enterprise-tier criterion. Cloud security profiles govern network, git, MCP, and integration access; CLI per-action approvals are a different control system. Customer-managed Outposts must enforce their published network policy themselves.

Cloud sessions use isolated execution machines. CLI OS sandboxing is a Research Preview, is unsupported on native Windows, and has separate Linux dependencies. Its network filtering is documented as unstable; direct edit/write tools operate outside the command-process sandbox. Bypass or reduced-interruption modes do not override organization-enforced deny/ask rules. These limitations should remain visible in deployment decisions.

Paid-plan Data Controls opt-out disables training and enables ZDR with model providers; Teams requires an administrator, while Enterprise training requires prior written consent. This is not blanket zero retention at Cognition. A public DPA is available. Core processing locations in its tables are United States-based, with India support processing also listed; this does not establish exclusive geographic residency. Customer Dedicated hosting is Cognition-managed, and Outposts moves execution to customer infrastructure while inference/planning remains in Devin Cloud.

Subprocessor disclosure is confirmed as **has** in the refreshed merged findings: the public DPA identifies Appendix C as its current named roster with purposes and locations. Its scope is Customer Data processed under the applicable customer agreement, excluding Account Data, rather than every supplier processing every customer's data. The second table applies to Personal Data submitted as Input; starred Databricks, xAI, and Snowflake entries apply only if enabled in Devin Desktop and do not establish Cloud suppliers. Verification of this public roster does not require gated access. Detailed Trust Center security documents still require access approval and an NDA and were not inspected. Saved-secret output masking is documented, but unregistered-secret detection before inference or disk writes remains uncertain. Enterprise attribution filtering is partial, support-enabled, and not evidence of generated-output IP indemnity.

## Constraints

**Evidence gaps:** the canonical [homepage](https://devin.ai/) and [pricing page](https://devin.ai/pricing) both returned HTTP 404 on October 11, 2026. Current self-serve documentation lists Pro at $20/month, Max at $200/month, and Teams at an $80/month minimum with $40/month full seats, but these prices could not be checked against the page the documentation calls authoritative. Exact numerical quotas and a complete cross-plan feature matrix were not established. NDA-gated Trust Center resources and private enterprise commitments were not accessed.

**Do not promote uncertain findings:** meaning-based semantic retrieval, native non-MCP custom-tool registration, dependency-to-CVE scanning, pre-disk-write diff acceptance, generic image-to-new-code generation, unregistered-secret scanning, customer-controlled inference backends, and full zero-network operation remain uncertain in the supplied merged results. Desktop per-hunk accept/reject controls do not settle when edits reach disk. Federal air-gapped CLI/Desktop statements and diagnostic commands do not establish generally available zero-connectivity operation. Cloud dedicated hosting and Outposts are not offline inference.

**Cost and scope:** parallel sessions and workers add usage. Teams Automations and AI Review draw from shared on-demand credits; exhausting credits stops Automations and removes AI Review while retaining the smart diff viewer. Full seats include Desktop, flex seats do not. Legacy Desktop wording about dollar-valued usage should not override current self-serve quota mechanics. Custom subagents are experimental; Cloud/local tools and permission rules are not interchangeable. The public DPA roster confirms subprocessor disclosure, not universal supplier applicability; its starred Databricks, xAI, and Snowflake entries are conditional on Devin Desktop enablement, not evidence of Cloud use.

**Review and history:** generated code can contain bugs or insecure behavior; preserve human review, tests, and branch protections. The release-history entries are a selected, official-changelog-backed set newer than the June 24, 2026 cutoff, not a complete enumeration of every intervening Cloud, CLI, or Desktop release. No Desktop-only release history was verified here.
