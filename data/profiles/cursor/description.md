## Characteristics

Cursor is an AI-native coding assistant built by Anysphere, delivered primarily as a fork of Visual Studio Code but increasingly available as a family of first-party surfaces: the desktop editor, a standalone terminal agent (Cursor CLI), an official JetBrains integration via the Agent Client Protocol (ACP), a web application at cursor.com/agents, and a native iOS app. At its core, Cursor pairs an inline, ghost-text autocomplete ('Tab') with a general-purpose, autonomous Agent that can search a codebase semantically, edit multiple files, run terminal commands, and carry out multi-step programming tasks from a single natural-language instruction. Beyond the local, foreground Agent, Cursor documents Cloud Agents that execute asynchronously in isolated VMs (including a Self-Hosted Pool option that keeps tool execution inside a customer's own infrastructure while orchestration and model inference remain in Cursor's cloud), subagents that a parent agent can delegate scoped work to, and dedicated built-in agents such as Bugbot (automated PR review with Autofix) and the paired Security Reviewer / Vulnerability Scanner. The product also documents Plan Mode (an upfront, editable plan before execution begins), session Checkpoints (full-session rollback of Agent-made changes), and persistent Rules/Memories that carry project- and team-level context across sessions without the user re-entering it.

## Access methods

Cursor is reachable through several first-party surfaces rather than a single client. The primary surface is Cursor's own VS Code-fork desktop editor. A standalone command-line agent (Cursor CLI / cursor-agent) runs the same agent capabilities in a terminal without any IDE, including an interactive Shell Mode and a non-interactive, scriptable print mode (`-p`/`--print`) with JSON/stream-JSON output for CI and automation. Cursor is also officially available inside JetBrains IDEs (IntelliJ IDEA, PyCharm, WebStorm, and others) via the Agent Client Protocol, installed from the ACP Registry and authenticated with an existing Cursor account. A web application at cursor.com/agents provides core agent functionality - writing code, running background agents, reviewing diffs and PRs - from any desktop, tablet, or mobile browser with no local installation required (an installable PWA is offered only as an optional convenience). A native iOS app (public beta, on all paid plans) gives direct assistant access from a phone, including launching and controlling agents, voice input, model selection, and reviewing/merging PRs; no official native Android app was found, so Android access currently relies on the web dashboard or installing the web app as a PWA. For teams building custom, programmatic agent applications, Cursor also ships a Cursor Agent SDK (TypeScript and Python) that exposes the local agent loop, custom tool registration, and cloud-agent orchestration as an API surface distinct from the standard IDE chat UI.

## Internal tools and mechanisms

Cursor's agent draws on several documented internal mechanisms rather than a single monolithic model call. Codebase context is built from a semantic indexing pipeline that splits files into syntactic chunks, converts them into cached embeddings, and reuses near-identical existing indexes across a team's highly similar codebase copies to keep large-repository indexing fast and current. A 'shadow workspace' mechanism runs a proposed edit in a hidden window and feeds the running language server's lint diagnostics back into the edit loop before the change is finalized. Execution autonomy is layered rather than a single global switch: file edits apply without approval by default (except configuration files, which still require approval), terminal/shell commands require approval by default but can be governed by a separate Run Mode (an allowlist, an Auto-review LLM classifier, or Run Everything) configured in permissions.json, and MCP tool calls are gated by their own, independent approval setting. A native hooks mechanism (.cursor/hooks.json, repo-scoped, or ~/.cursor/hooks.json, user-scoped) lets an admin or user intercept lifecycle events - before/after shell execution, before/after file edit, pre/post tool use, subagent start/stop, and pre-compact - and return an allow/deny/ask decision or block the action outright. Custom subagents can be authored as Markdown files with YAML frontmatter under .cursor/agents/, each scoping its own tools (or a coarse read-only flag), disallowed tools, MCP servers, hooks, max turns, and skills.

## Workflows and use cases

Documented workflows span individual-developer and organizational/CI use. At the individual level, Cursor supports autonomous multi-step coding tasks driven by natural language, inline Tab completions while typing, a dedicated workflow for generating and backfilling unit test coverage, and turning a pasted design mockup image into working UI code via a vision-capable model. Plan Mode supports a research-plan-approve-execute workflow for larger, multi-file changes, with session Checkpoints available to roll back an entire Agent session if it goes wrong. At the team and CI/CD level, the CLI supports headless, scriptable invocation (JSON/stream-JSON output, documented exit codes) for use in GitHub Actions and other automation pipelines; Bugbot automatically reviews every pull request for bugs, security issues, and quality problems, with an Autofix capability that spawns cloud agents to propose fixes; and Automations let a cloud agent run on a cron schedule or in response to events (a GitHub/GitLab PR, a Slack message, a Linear issue, or a generic webhook) without an active user session initiating it. Multiple agents can also run genuinely in parallel, each in its own isolated Git worktree, from the Agents Window, and the built-in Security Reviewer / Vulnerability Scanner agents run on a schedule to flag security issues and outdated dependencies across a codebase.

## Integrations

Cursor's primary open extension point is the Model Context Protocol (MCP): MCP servers connect the agent to external tools and data sources (e.g. Google Drive, Notion, databases, other APIs) and are configured consistently across both the editor and the CLI. Cursor operates a vendor-curated Marketplace (cursor.com/marketplace) listing more than 30 third-party integrations from named partners such as Atlassian, Datadog, GitLab, Glean, Hugging Face, monday.com, and PlanetScale, alongside earlier launch partners including Amplitude, AWS, Figma, Linear, and Stripe. For organizations, admins can configure 'Team MCP' servers once and distribute them across cloud agents, the Agents Window, the IDE, and the CLI through a governed Team Marketplace supporting SCIM-group and organization-group-based access control, so individual developers do not need to configure MCP servers themselves. Cursor also documents native Git tooling (AI-generated commit messages, merge-conflict resolution assistance directly from chat, agent attribution, Cursor Blame) and first-party GitHub/GitLab integration for opening pull requests directly from the Agent or Cloud Agents.

## Security

Cursor documents a layered security and compliance posture. Enterprise identity and access controls include SAML 2.0 SSO (supporting Okta, Azure AD, Google Workspace, and other IdPs) with SCIM provisioning and the ability to enforce SSO and disable local login, plus fine-grained RBAC across organizations, teams, and agents; an Audit Log tracks 19 event types and can be exported as CSV. Cloud/background agent execution can be constrained with sandbox network allow-lists (three configurable levels, up to organization-wide enforcement from the admin dashboard) and, for Enterprise customers, a Self-Hosted Pool option that keeps tool execution inside customer-managed infrastructure while orchestration and model inference remain in Cursor's cloud. Cursor's LLM Safety and Controls documentation describes multi-stage secret detection - scanning prompts before submission to the LLM, files before the agent reads them, and generated code before it is written to disk - while also noting these are rules the model is instructed to follow rather than hard guarantees, and recommending they be paired with enforcement hooks. Data protections include AES-256 encryption at rest and TLS 1.2+ in transit, a standing Data Processing Addendum, a publicly itemized sub-processor list, an opt-in 'Privacy Mode' backed by zero-data-retention agreements with model providers, and stated SOC 2 Type II compliance (attestation available on request) alongside GDPR/CCPA compliance. Data residency is US-only by default for inference, processing, and storage, with EU + Iceland inference-only coverage available on request to Enterprise customers and broader regional coverage described as still in development.

## Constraints

Several of Cursor's more powerful capabilities are gated to specific plans or deployment modes rather than being universally available. SSO/RBAC, the Audit Log, LLM Safety and Controls (secret scanning), the Security Reviewer/Vulnerability Scanner agents, and Self-Hosted Pool execution are documented as Teams/Enterprise features, not part of the free Hobby or individual Pro tier. Cursor does not document a fully offline or air-gapped operating mode: even the Self-Hosted Pool keeps agent orchestration and model inference in Cursor's cloud, and the officially documented custom-model override (pointing Settings > Models at an OpenAI-compatible base URL - the supported path for self-hosted/local models such as Ollama) still requires a network-reachable endpoint rather than a purely local, disconnected one. Full VM-level sandboxing is documented specifically for Cloud Agents; the default local/foreground Agent runs directly on the user's machine, with only best-effort, per-command shell sandboxing under certain Run Modes rather than a hard security boundary. Data residency is US-only by default, with EU+Iceland coverage limited to inference only and available on request rather than as a self-service, all-region guarantee. IP indemnification is set out in Cursor's Master Services Agreement, which applies to organizations with a negotiated Enterprise agreement rather than to individual Free/Pro subscribers under the standard Terms of Service (where indemnification instead runs from customer to vendor), and is subject to carve-outs such as disabled safety filters or known-infringing use. Native mobile access is currently iOS-only; Android relies on a web dashboard or an installable PWA rather than a dedicated native app. Finally, subagents inherit the parent agent's configured MCP servers/tools by default rather than allowing independent, per-subagent MCP attachment, and registering a custom tool without standing up an MCP server is currently a Cursor Agent SDK capability rather than a setting exposed in the standard IDE chat UI.
