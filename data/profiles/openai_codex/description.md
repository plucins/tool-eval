## Characteristics

OpenAI Codex is OpenAI's coding agent, offered as a desktop app, a standalone CLI, an IDE extension, a cloud service and a mobile experience that all share ChatGPT-account or API-key authentication. It is agent-first: it plans and executes multi-step work, edits files across a repository from natural-language instructions, runs shell commands inside a sandbox, and can keep working toward a persistent goal (Goal mode) until done, paused or in need of input. Documentation emphasises prompt-driven workflows (writing tests, refactors, bug fixes, migrations) rather than as-you-type suggestions; inline ghost-text completion was not confirmed in the reviewed official pages. The CLI is open source (Apache-2.0 repository) and ships frequent releases, several per week at the time of writing.

## Access methods

Codex is reachable through several surfaces: the ChatGPT desktop app, the standalone Codex CLI (installable with npm and other methods), an IDE extension for VS Code and compatible editors (Cursor, Windsurf), Codex Cloud and web access, and the ChatGPT mobile app, which drives tasks running in Cloud or on a connected Mac or Windows PC. Sign-in is with a ChatGPT plan or with an OpenAI API key. Pricing lists web, CLI, IDE and iOS access from Plus upward, whereas Free and Go list only the desktop app with a lightweight model, and API-key use has no cloud-based features. A codex exec non-interactive mode and an official GitHub Action cover headless and CI use, and an experimental app-server lets custom clients drive Codex.

## Internal tools and mechanisms

Codex executes shell commands itself under an OS-enforced sandbox (Seatbelt on macOS, bubblewrap on Linux/WSL2, a native Windows sandbox) combined with an independent approval policy, giving separately configurable sandbox and approval levels, presets and a /permissions command. Project guidance is loaded automatically from AGENTS.md files with global, repository and nested-directory layering, and opt-in local memories can carry context between chats. Lifecycle hooks (PreToolUse, PermissionRequest, PostToolUse, Stop and others) can run scripts or MCP tools and block operations. Subagent workflows are on by default, with user-defined custom agents in TOML files (though custom agents inherit the parent's sandbox, approval policy and MCP servers). Long sessions rely on configurable history compaction; no semantic code index was confirmed in the pages reviewed. Slash commands such as /plan, /goal, /review and /fork expose planning, goal-setting, review and forking.

## Workflows and use cases

Documented workflows include unattended CI runs via codex exec and the GitHub Action, automated pull request review on GitHub (and a local /review command), long-running verifiable goals such as language migrations, security backlog triage with Codex Security, scheduled recurring tasks, and image-driven UI fixes. Work can be isolated in Git worktrees or cloud environments so several independent chats run in parallel, and cloud tasks can end in a commit or pull request. Best-practice guidance recommends asking Codex to create tests, run checks and review the work before accepting it. Self-correction is driven by user-supplied verification criteria (tests, builds) rather than a built-in always-on test loop.

## Integrations

Extensibility is built on MCP (local or remote servers added from the CLI, including OAuth sign-in) and a plugin system that bundles skills and MCP servers, listed in a single plugin directory shared by ChatGPT and Codex with partner plugins such as Slack, GitHub, GitLab, Notion, Supabase and Vercel. GitHub integration provides automatic pull request review and an Actions workflow; GitLab merge request review is in preview. Slack and GitHub code review are cloud-based integrations that are not available with API-key authentication. The IDE extension does not support plugins, and some plugins are desktop-only. Codex can also be pointed at custom model providers (for example a local Ollama endpoint) through configuration.

## Security

Local execution is sandboxed with network access off by default, and Codex Cloud runs tasks in isolated OpenAI-managed containers with internet access blocked during the agent phase unless admins enable it, optionally limited by a domain allowlist and allowed HTTP methods. Enterprise workspaces get RBAC, SSO and SCIM-based group provisioning, a Compliance API and analytics for auditing (local actions are not guaranteed to be fully recorded). OpenAI states business data is not used for training by default and is encrypted at rest and in transit (AES-256, TLS 1.2+); qualifying customers can configure retention and data residency in several regions, with in-region inference in the US or Europe. A Data Processing Addendum, public sub-processor list and an IP infringement indemnity under the Services Agreement are published for business customers. Automatic secret detection/redaction in prompts was not confirmed in the reviewed pages, although recent releases add credential masking for supported remote commands.

## Constraints

Several capabilities depend on plan or surface: cloud features need a ChatGPT sign-in on a qualifying plan, while API-key use excludes cloud-based integrations. Mobile availability depends on rollout and workspace settings, and project-scoped scheduled tasks need the computer on and the desktop app running. Compliance, residency and retention controls target Enterprise, Edu, Business and API customers, and Work with local computer access does not provide strict zero data retention. Some features are previews (GitLab review, Security Review, Codex Security Cloud) or experimental (app-server dynamic tools). Custom agents cannot attach their own MCP servers or separate sandbox. Not confirmed in the pages reviewed: whole-session checkpoint/rollback, a semantic codebase index, inline completion, fully offline operation, and on-premises deployment of the Codex service. Model availability changes over time, for example GPT-5.5 retiring from ChatGPT-signed-in Codex on 14 October 2026.
