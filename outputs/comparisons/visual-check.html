Cursor

Current · researched 2026-07-25T06:32:43Z

Characteristics

Cursor is an AI-first code editor built on a VS Code base. Its agent plans and executes multi-step tasks, generates code from natural language, offers inline (Tab) completion, and edits coordinated changes across multiple files. It indexes the repository for codebase-wide semantic search and supports large-repository/long-context work, including a Max Mode for larger context windows on supported models.

Access methods

Cursor is available as a standalone desktop editor (macOS, Windows, Linux), through an officially supported JetBrains integration, as a standalone CLI (including a headless mode for CI), and via browser and mobile access to its cloud agents. Users can choose between frontier models from multiple providers.

Internal tools and mechanisms

The agent runs terminal commands under a configurable approval model and can execute in an OS-native sandbox (Seatbelt on macOS, Landlock/seccomp on Linux). It coordinates sub-agents in separate context windows and can run background/cloud agents asynchronously. Persistent Project Rules (.cursor/rules) and AGENTS.md carry project-scoped instructions across sessions.

Workflows and use cases

Typical workflows include autonomous multi-file feature implementation with a reviewable diff before apply, automated pull-request review via Bugbot, large-scale codebase modernization using semantic search and multi-file editing, and governed enterprise rollouts with SSO, audit logging, and enforced privacy mode.

Integrations

Cursor supports the Model Context Protocol (MCP) for connecting external tools and data sources, a first-party Plugins system on the Cursor Marketplace, and native git and GitHub integration (AI commit messages, and opening pull requests directly from background agents).

Security

Cursor documents a customer-facing Privacy Mode (no code stored/trained on when enabled; enforced by default on Business/Enterprise), enterprise SSO (SAML/OIDC) with SCIM provisioning and role-based access control, admin audit logging, and self-hosted cloud agents that keep code and build execution in the customer's own infrastructure. An IP-indemnification commitment is documented in the enterprise agreement for eligible plans.

Constraints

Several capabilities are plan-gated to Business/Enterprise (SSO/SCIM, audit logs, enforced privacy mode, self-hosted agents). The native mobile app is iOS-only and in beta; pull-request creation is GitHub-oriented and requires connecting the integration. Cursor does not offer a public-code duplication filter (only the indemnity limb of that criterion is met), and full platform on-premises deployment is not offered (only agent-execution self-hosting). Static-analysis-into-AI integration was left uncertain pending an official source.

Additional facts

  • Platform and access surfaces:

    Cursor is a standalone AI code editor built on a VS Code base, and also ships an officially supported JetBrains integration, a standalone CLI (macOS/Linux/Windows, incl. headless CI mode), and browser/mobile access to its cloud agents.

  • Model choice:

    Cursor lets users choose between frontier models from multiple providers (OpenAI, Anthropic, Google, xAI) and offers a Max Mode with a larger context window on supported models.

  • Plans and tiers:

    Cursor is offered across Free, Pro, Business, and Enterprise tiers; several governance features (SSO/SCIM, audit logging, enforced privacy mode, self-hosted cloud agents) are gated to Business/Enterprise.

Use cases

  • Automated pull request review (documented) —

    Cursor's Bugbot reviews pull requests automatically, posting inline comments on potential bugs and offering one-click fixes.

  • Autonomous multi-file feature implementation (documented) —

    Describe a change in natural language and let the Cursor Agent plan the work, edit across multiple files, run terminal commands, and present the result as a reviewable diff before it is applied.

  • Large-scale codebase modernization (inferred) —

    Use the agent, whole-repo semantic search, and multi-file editing to carry out framework migrations and structural refactors across a large repository.

  • Governed enterprise rollout (inferred) —

    Deploy Cursor across an organization with SSO/RBAC, admin audit logs, enforced privacy mode, and self-hosted execution for the agent's code and build steps.

Claude Code

Current · researched 2026-07-24T07:43:15Z requires_research

Characteristics

Claude Code is Anthropic's agentic coding tool that lives in the terminal, understands your codebase, and carries out routine development tasks through natural-language commands. Rather than offering as-you-type completions, it acts as an autonomous agent: given a plain-language goal it searches for relevant files, reads them for context, makes coordinated edits across the project, runs commands and tests to verify its work, and can commit the result when asked. It works across multiple files and tools to complete multi-step tasks, and it can delegate focused subtasks to separate subagent instances.

Access methods

Claude Code is primarily a command-line tool that runs in your terminal and works alongside your existing IDE without changing your workflow. Native IDE extensions are available for VS Code (plus VS Code forks such as Cursor and Devin Desktop) and for JetBrains IDEs, and a browser-based experience, Claude Code on the web, runs coding tasks on Anthropic-managed cloud infrastructure at claude.ai/code. It is available across Anthropic's Pro, Max, Team, and Enterprise plans, with some newer surfaces (such as the web app) offered as research previews to specific tiers.

Internal tools and mechanisms

Claude Code operates through a set of built-in tools: it reads and edits files, and executes Bash commands under a permission-based model where read-only commands run without a prompt while system-modifying commands require explicit approval. It supports running commands in the background so long-running processes do not block work, and it can spawn subagents to isolate context and run analyses in parallel. Behavior can be extended and governed with hooks (for example running a linter after edits and feeding results back to the model) and with Model Context Protocol (MCP) servers that connect external tools, databases, and APIs. Project guidance persists across sessions through CLAUDE.md memory files and an auto-memory system.

Workflows and use cases

Representative workflows include refactoring legacy code across many files from a single instruction, generating and running unit tests then fixing failures, and handling git operations such as creating commits with generated messages and opening pull requests via the GitHub CLI. On Team and Enterprise plans it can perform automated pull request reviews on GitHub, posting inline comments about logic errors, security issues, and regressions. It is also designed for large-codebase and monorepo work, using agentic search and long-context handling to explore and answer questions across an entire repository.

Integrations

Claude Code connects to hundreds of external tools and data sources through the Model Context Protocol (MCP), an open standard for AI-tool integrations that exposes issue trackers, monitoring dashboards, databases, and other services. It integrates with GitHub through the gh CLI for creating issues, opening pull requests, and reading comments, and it supports the automated Code Review workflow on GitHub PRs. For enterprise deployment, it can run against Claude models hosted in a customer's existing Amazon Bedrock, Google Cloud Vertex AI, or Microsoft Foundry instances.

Security

Claude Code uses a permission-based execution model and, by default, shows each proposed file edit as a side-by-side diff for accept/reject before writing to disk. It can run commands inside OS-level sandboxes (Seatbelt on macOS, bubblewrap on Linux and WSL2) and in more isolated environments up to full VMs or Anthropic-managed cloud sandboxes. Under commercial terms, code and prompts are not used to train Anthropic's models unless the customer opts in, and Enterprise organizations can configure custom data-retention and zero-data-retention arrangements. Enterprise and Team plans add SSO (SAML/OIDC), role-based permissions, SCIM provisioning, and organization-wide managed policy settings that override local configuration.

Constraints

Claude Code does not provide as-you-type inline code completion; it is an agent driven by explicit natural-language instructions. It deliberately builds no semantic/embedding index of the codebase, instead using live agentic search (file reads, grep/glob, and LSP symbol lookups), so external code-search or RAG indexes must be added via MCP. Several capabilities are gated by plan or release stage: managed Code Review is a research preview limited to Team and Enterprise subscriptions, Claude Code on the web is a research preview for specific tiers, the extended 1M-token context window is available only on certain newer models, and private deployment relies on the customer's own Bedrock/Vertex/Foundry cloud rather than a fully air-gapped self-hosted product.

Additional facts

  • Platform and access surfaces:

    Claude Code is primarily a terminal CLI that runs alongside the developer's existing IDE, with native extensions for VS Code (and forks such as Cursor and Devin Desktop) and JetBrains IDEs, plus a cloud-hosted web experience at claude.ai/code.

  • Data usage:

    Under commercial terms, Anthropic does not use code or prompts sent to Claude Code to train its generative models unless the customer explicitly opts in, and Enterprise/commercial organizations can configure custom data-retention and zero-data-retention arrangements.

  • Models and context handling:

    Claude Code runs on Anthropic's Claude models and manages long sessions with automatic compaction near the context limit; extended 1M-token context windows are supported on specific newer models. Enterprises can also run Claude Code against Claude models hosted in their own Amazon Bedrock or Google Cloud Vertex AI instances.

  • Plans and availability:

    Claude Code is offered across Anthropic's Pro, Max, Team, and Enterprise plans, and some capabilities are gated to higher tiers. For example, Claude Code on the web is available for Pro, Max, and Team users and for Enterprise users with premium or Chat + Claude Code seats, while managed Code Review is limited to Team and Enterprise subscriptions.

  • Release stage:

    Several newer Claude Code capabilities are offered as research previews rather than general availability, including the browser-based Claude Code on the web and the managed GitHub Code Review workflow.

Use cases

  • Automated pull request review on GitHub (documented) —

    On Team and Enterprise plans, Claude Code can review GitHub pull requests automatically, analyzing changes for logic errors, security vulnerabilities, and regressions and posting findings as inline comments.

  • Generate and run unit tests for existing code (documented) —

    A developer asks Claude Code to write unit tests for specified functions; it locates the relevant code, writes the tests, and can run them and fix any failures.

  • Onboard onto and navigate a large codebase (inferred) —

    An engineer joining an unfamiliar monorepo uses Claude Code to answer meaning-based questions across the whole repository, relying on agentic search and long-context handling while project conventions persist between sessions via CLAUDE.md.

  • Refactor legacy code across multiple files (documented) —

    A developer asks Claude Code in natural language to modernize or restructure existing code; it searches for the relevant files, reads them for context, and applies coordinated edits across the codebase before verifying the result.

  • Governed enterprise rollout with isolation and data controls (inferred) —

    A platform team deploys Claude Code across the organization with SSO and role-based access, runs agent commands inside OS-level sandboxes, keeps data in their own cloud via Bedrock/Vertex, and relies on the no-training-by-default commercial terms.

Windsurf

Current · researched 2026-07-25T06:47:24Z

Characteristics

Windsurf is an agentic AI IDE whose core is Cascade, an agent that plans and executes multi-step tasks, generates code from natural language, offers inline Tab completion, and edits across multiple files. It indexes the codebase for meaning-based retrieval (RAG/M-Query) and supports large repositories through remote indexing and a Fast Context retrieval subagent.

Access methods

Windsurf is available as a standalone editor (the Windsurf Editor) and as officially supported plugins for many editors including VS Code, JetBrains, Visual Studio, Vim/NeoVim, Emacs, Xcode, Sublime Text, and Eclipse. It does not provide an official mobile app or a browser-hosted assistant; core functionality requires a local install.

Internal tools and mechanisms

Cascade runs terminal commands under configurable auto-execution levels with allow/deny lists, coordinates parallel multi-agent sessions via git worktrees and the Agent Command Center, runs background/cloud agents on managed VMs, and persists auto-generated memories plus rules files across sessions.

Workflows and use cases

Typical workflows include agentic multi-file feature builds with a reviewable diff, automated GitHub pull-request reviews, enterprise self-hosted rollouts with SSO and audit logging, and cross-editor AI assistance through the official plugins.

Integrations

Windsurf natively supports the Model Context Protocol (user-supplied MCP servers via stdio/HTTP/SSE) and provides a vendor-curated plugin store and recommended-plugins catalog (Jira, Figma, GitHub, SonarQube, Snyk, and others). Native git includes AI commit messages; pull-request creation is available through an external GitHub MCP server rather than a first-party feature.

Security

Windsurf documents customer-facing data-retention/training opt-out (zero data retention on paid plans), enterprise SSO (SAML) with SCIM provisioning and RBAC, admin analytics and audit/attribution logging, an Enterprise attribution/duplication filter with an IP-infringement indemnification commitment, and fully self-hosted, air-gapped, or hybrid (VPC) deployment.

Constraints

Several governance capabilities (SSO/SCIM, RBAC, audit, duplication filter, self-hosting) are gated to Teams/Enterprise. Windsurf Reviews is beta and limited to GitHub Cloud with per-PR and monthly caps. There is no official mobile app, no browser-hosted assistant, and no host-isolated execution sandbox (execution runs in the local terminal). Standalone CLI status is uncertain amid an ongoing Windsurf-to-Devin product rebrand, and native PR creation requires an external MCP integration.

Additional facts

  • Platform and access surfaces:

    Windsurf ships as a standalone AI IDE (the Windsurf Editor) and as plugins for a wide range of editors (VS Code, JetBrains, Visual Studio, Vim/NeoVim, Emacs, Xcode, Sublime, Eclipse). It does not offer an official mobile app or a browser-hosted assistant.

  • Cascade agent:

    Cascade is Windsurf's agentic core: it plans and executes multi-step tasks in Write/Plan modes, runs terminal commands, retrieves context via codebase indexing, persists memories and rules, and integrates MCP servers.

  • Plans and deployment:

    Windsurf is offered across Free, Pro, Teams, and Enterprise tiers. Enterprise adds SSO/SCIM, RBAC, admin analytics/audit, zero-data-retention controls, and self-hosted / air-gapped / hybrid (VPC) deployment.

Use cases

  • Agentic multi-file build with Cascade (documented) —

    Describe a feature and let Cascade plan the work, generate and edit code across multiple files, run terminal commands, and present changes as a reviewable diff before applying.

  • Automated GitHub pull request reviews (documented) —

    Windsurf Reviews analyzes GitHub pull requests and posts review comments automatically for Teams/Enterprise customers.

  • Cross-editor AI assistance (inferred) —

    Use Windsurf's inline completion, semantic codebase search, and Cascade agent inside an existing editor of choice via the official plugins.

  • Enterprise self-hosted rollout (inferred) —

    Deploy Windsurf across an organization with SSO/SCIM and RBAC, admin analytics/audit logging, enforced zero-data-retention, and self-hosted or air-gapped infrastructure.

GitHub Copilot

Current · researched 2026-07-24T09:42:45Z

Characteristics

GitHub Copilot is an AI coding assistant from GitHub (Microsoft) that spans inline code completion, a conversational assistant (Copilot Chat), and an autonomous "agent mode"/coding agent. It generates code from natural language, edits and refactors across multiple files, generates tests, reviews pull requests, and can plan and execute multi-step tasks. It is delivered as a cloud service and is available across several IDEs, a standalone CLI, the web, and mobile. Capabilities and limits vary by plan (Free, Pro, Pro+, Business, Enterprise) and, for newer capabilities, by release stage.

Access methods

Copilot is officially supported across multiple editors and surfaces: Visual Studio Code, Visual Studio, JetBrains IDEs, Neovim, Xcode, and Eclipse; a standalone command-line interface; the web (Copilot Chat and immersive mode on github.com); and GitHub Mobile (iOS/Android). Availability of individual surfaces and features can depend on the active plan.

Internal tools and mechanisms

Beyond inline suggestions, Copilot exposes agent mode (which selects files, proposes edits and terminal commands, and iterates until a task is complete), Copilot Edits with a reviewable accept/discard diff workflow, and a background coding agent that runs in an isolated GitHub Actions environment. It indexes repositories for meaning-based (semantic) codebase search, applies persistent custom instructions (e.g. repository- and organization-scoped instruction files) across sessions, and can be extended with external tools through the Model Context Protocol (MCP) and Copilot Extensions.

Workflows and use cases

Documented workflows include: as-you-type inline completion; natural-language-to-code generation; coordinated multi-file changes; automated and instruction-driven refactoring; automated test generation; automated code review on pull requests; native git operations (commit-message generation, branch/commit automation via the coding agent); and pull-request creation, where the coding agent can open a PR and write its description. The autonomous coding agent can take a task and drive it to a proposed pull request.

Integrations

Copilot documents an official extensibility and integration surface: the GitHub Marketplace catalog of Copilot-compatible apps and extensions, Copilot Extensions, and MCP-based integrations (including a curated GitHub MCP Registry of partner and community MCP servers) for connecting external tools and data sources.

Security

For organizational use Copilot documents enterprise single sign-on (SAML SSO) with SCIM provisioning and role-based administration of Copilot policies; customer-facing controls to opt out of model-training use and to exclude repository content (content exclusion); a public-code duplication/"suggestions matching public code" filter together with IP indemnification for eligible Business/Enterprise plans; and audit logging plus usage metrics for administrators. Several of these controls are gated to Business or Enterprise plans.

Constraints

Copilot is delivered only as a multi-tenant cloud (SaaS) service: no on-premises or dedicated private-cloud deployment of the Copilot service is documented (research status: not found across official documentation, product, pricing, and changelog sources). Many capabilities are gated by plan tier (notably Business/Enterprise for enterprise security and administrative controls) or are offered at a preview/beta release stage, and some features are specific to particular IDEs. Feature availability should be re-checked against the cited official sources, which change frequently.

Additional facts

  • Free tier limits:

    Copilot Free gives individual developers a limited, no-cost entry point capped at a fixed monthly allowance of code completions and chat messages, with models available only through automatic model selection.

  • Extensibility via MCP:

    Copilot Chat can be extended with external tools and services through the Model Context Protocol (MCP), an open standard for sharing context with large language models, letting teams connect Copilot to a wide range of existing tools.

  • Plans & pricing:

    Copilot is sold in individual tiers (including a free tier and paid Pro-level tiers) and organizational tiers (Copilot Business and Copilot Enterprise). Copilot Business is priced at $19 per user per month and Copilot Enterprise at $39 per user per month, with Enterprise adding a larger AI-credit allowance and earlier access to new models and features.

  • Vendor identity:

    GitHub Copilot is an AI coding assistant offered by GitHub (a Microsoft subsidiary), positioned as an 'AI pair programmer' that assists across the software development lifecycle.

Use cases

  • Multi-file changes with agent mode in the editor (documented) —

    Within the IDE, a developer uses Copilot agent mode to understand the project and make coordinated edits spanning multiple files, moving from explanation through to validated changes.

  • Automated pull request review (documented) —

    A developer requests a Copilot code review on a pull request; Copilot analyzes the change, flags issues, and proposes fixes that can be applied directly.

  • Delegate a background task to the cloud coding agent (documented) —

    A developer assigns a task to the Copilot cloud agent, which works independently in the background to research the repository, plan an implementation, and make code changes on a branch.

  • Onboard quickly to an unfamiliar codebase (inferred) —

    A newly assigned engineer uses Copilot Chat and codebase search to ask natural-language questions about how an unfamiliar repository is structured and what specific modules do, accelerating ramp-up before making changes.

  • Raise test coverage on a legacy module before release (inferred) —

    A team facing a release deadline asks Copilot to generate and debug unit tests for an under-tested legacy module, then delegates broader test-suite expansion to the cloud agent as a background task.
